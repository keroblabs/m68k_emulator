# 02 — MC68K/8 (Board 004)

Status: first physical target; component choices and memory organization agreed. Register addresses, pin assignments and electrical/timing details await schematic review.

## Hardware

- MC68008 DIP48, 8-bit external data bus, 20-bit address bus (1 MiB CPU address space). Five processors already available.
- 256 KiB ROM, 1 MiB physical SRAM, of which 512 KiB is visible at a time.
- Yamaha V9958 (successor to TMS9918), 128 KiB display VRAM plus 64 KiB expansion VRAM.
- YM2149 programmable sound generator, also driving keyboard selection.
- Exactly one MC68681 DUART, providing serial channels, system timer and GPIO.
- 16 × 8 keyboard matrix, SD card over SPI implemented through MC68681 GPIO.
- 5 V glue logic candidate: ATF1508AS or appropriate 5 V EPM7128 family device. The 3.3 V ATF1508ASV is not the intended part.
- SD card operates at 3.3 V; the current hardware design already includes level shifters. Exact schematic and direction/timing must be reviewed.

Clock rate, ROM technology, exact SRAM part, V9958 VRAM implementation and CPLD package remain open. Two 512K × 8 SRAMs (e.g. AS6C4008 family, subject to electrical/package verification) are a candidate. V9958 sourcing and authenticity need verification; inventory is not a purchase commitment.

## Memory architecture (agreed)

| CPU range (inclusive) | Size | Purpose |
| --- | ---: | --- |
| 0x00000–0x3FFFF | 256 KiB | ROM |
| 0x40000–0x7FFFF | 256 KiB | I/O |
| 0x80000–0xEFFFF | 448 KiB | Fixed SRAM |
| 0xF0000–0xFFFFF | 64 KiB | Banked SRAM |

Prefer the single 64 KiB window over four independently banked windows or a 256 KiB window: large contiguous fixed memory is more valuable for application code, heap, stacks and graphics work. There are sixteen physical 64 KiB SRAM pages. Proposed translation: CPU fixed region maps pages 0–6, the top window maps pages 7–15 through a four-bit bank register. Default bank 7 gives a contiguous 512 KiB RAM map at reset. All 1 MiB is accessible, 448 KiB fixed plus nine 64 KiB selectable pages. Values 0–6 must have explicitly specified behaviour (proposal: reject/retain previous bank, rather than silently alias fixed pages). A0–A15 pass through; translated high address bits and SRAM chip selects come from glue logic. Bank register readback and reset semantics must be defined and tested. Keep stacks, interrupt handlers and bank-switching code in fixed RAM or ROM; do not cross bank boundaries with unguarded multi-byte accesses.

I/O decoding is not locked. Candidate 16 KiB windows: 0x40000 DUART, 0x44000 YM2149, 0x48000 V9958, 0x50000 bank register, 0x54000 system ID/control. Reserve other windows; **no separate SPI controller is required**, since SD connects to DUART GPIO. Final addresses follow KiCad and firmware/emulator agreement, not this candidate list.

## Keyboard and DUART

YM2149 Port A bits 3–6 drive a 4-to-16 row decoder; bits 0–2 drive an 8-to-1 column mux. MC68681 IP5 senses the selected cell (current emulator assumes active-high). Seven output lines and one input address 128 positions. Port A bit 7 and PSG Port B are unallocated unless schematic indicates otherwise. Validate pull resistors, active levels, settling, simultaneous keys/ghosting and diode requirements on hardware.

Use the DUART counter/timer for a nominal 1 ms tick, with appropriate vectored interrupt and acknowledge. Both UART channels are available for debug/communications when the matrix keyboard is used. Preserve shared GPIO bits when changing SD outputs and ensure keyboard IP5 does not collide with SD MISO. Firmware should emit nonblocking input events; test rapid taps, debounce, modifiers, releases and repeat. Current 10 ms/row yields 160 ms full scan, exceeding the emulator's 120 ms release extension; investigate 1–2 ms/row and realistic debounce. Fix unassigned function-key events and duplicated modifier-state handling as needed.

## Video and sound

Use V9958 with 128 KiB normal display VRAM and 64 KiB expansion VRAM. Expansion memory is not directly displayable; verify supported CPU/command-engine accesses and transfers. Support compatible text/graphics modes, palette ports, extended registers, sprites, scrolling, status/interrupts and hardware commands (copy, fill, line, CPU transfers). Begin with text monitor then bitmap modes and game demos. Possible 512 × 212 16-colour mode has 53 KiB visible pixel data per page, with hardware page alignment to be respected. Native video wiring/port ordering, VRAM DRAM requirements, encoder (CXA2075 family candidate) and timing require hardware review.

Keep the TMS9918 as a legacy emulator option. Correct its write address control bit and preserve full register bytes. YM2149 currently models register configuration and GPIO only; implement tone, noise, envelope, mixer, amplitude and host audio. Protect shared address-latch transactions between audio and keyboard operations. Add mixer control API that preserves GPIO direction bits.

## SD and native applications

SD SPI hangs on MC68681 GPIO, not a dedicated CPLD SPI master or YM2149 Port B. Firmware bit-bangs MOSI, clock and chip select on suitable DUART output pins and samples MISO on an available input. Exact pin assignments, level shifting, idle levels, initialization clock and feasible throughput need schematic/bench validation. Use the DUART set/reset registers with masks preserving unrelated outputs. In the emulator attach a signal-level SD SPI card model to the same GPIO callbacks; combine keyboard IP5 and SD MISO without one overwriting the other. Support initialization, card addressing, 512-byte sector read/write, errors and persistent disk images. Start with SDHC if suitable, explicitly define supported card variants.

Use FAT16/FAT32 (FatFs is a candidate) over a block-device API. ROM monitor supports directory listing, load, run and diagnostics; compile on Linux, copy files to SD, insert and run. Start with fixed-address binaries and defined load bounds; later consider header with entry point, load address, image/BSS size and version. Protect monitor, stack and bank window from invalid loads. Games can use banked resources, VDP sprites/commands and YM2149 music. Potential demos: Tetris, Breakout, maze games, scrolling shooters and native adventure games. Advanced debugging occurs in the emulator.

3. Verify RAM translation, reset and all nine selectable pages; ensure fixed data remains intact across changes.
4. Implement V9958 and PSG sound; test graphics/interrupts and simultaneous keyboard/audio.
5. Implement DUART GPIO SD transport, FAT16/FAT32 and load/run.
6. Review schematic against emulator map, fit CPLD RTL and verify electrical levels, bus strobes, DTACK/wait states, interrupt acknowledgement, pin count, reset and timing; progress in parallel where possible.
7. Manufacture and bring up hardware using known-good firmware and SD images.

CPLD fitting, hardware equivalence and physical performance are not yet demonstrated.
